Architecture Decision

Two files.
Two responsibilities.

The most important engineering decision: business logic is separated from UI, so the NLP engine is fully testable without React, DOM or browser.

StudyBot/src
├── studybot.logic.js
│    pure functions · NLP · generators
└── StudyBot.jsx
     React UI · state · animations
validateInput → extractSentences → extractKeyTerms → generateFlashcards → generateSummary → generateQuiz

CI/CD

Every push.
Every PR.
Green pipeline first.

GitHub Actions runs two parallel jobs: JavaScript tests with Vitest and Python linting with Ruff.

Job 1 — Vitest

Runs all unit tests and coverage checks before merging.

Job 2 — Ruff

Checks Python files and keeps the repository clean.

Result

No merge without a green pipeline.

The Big Fail

350 MB

Transformers.js model download on first use made the app practically unusable.

The Fix

Revert.

We replaced it with a custom TF‑IDF + German suffix stemmer. Lesson learned: spike branch first. Always.

Lessons Learned

The engineering lessons were bigger than the features.

🏗️
Architecture first

Early separation of logic and UI made every later step easier.

🧪
Spike before dependency

External libraries must prove themselves before becoming core architecture.

📊
Read coverage

Coverage reports are not decoration — they reveal weak branches.

🛡️
CI saves you

Git workflow and tests protect the team from accidental breakage.

🇩🇪
German NLP is special

Inflection and generic adjectives need stronger filtering.

🧭
Real users matter

Personas kept the project focused on actual student pain.

Tech Stack

Small stack.
Strong result.

No backend. No database. No AI API. The product is a fast static SPA with a custom local NLP engine.
